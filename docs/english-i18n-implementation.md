# TG Vault 语言设置与翻译维护

本文替代早期英语迁移计划，说明当前语言规则和翻译维护要求。

## 语言设置

Web 和 Telegram Bot 支持简体中文（`zh-CN`）、英语（`en`）和俄语（`ru`），默认及缺失翻译的回退语言为简体中文。

- **Web**：优先使用用户选择，其次匹配浏览器语言，均不可用时使用简体中文。选择保存在浏览器的 `tg-vault.locale`；旧的明确中文偏好会迁移到该键。
- **Bot**：优先使用已保存的选择，其次匹配 Telegram 的 `language_code`，最后使用简体中文。可通过 `/language` 修改；偏好按 Telegram `user_id` 保存。
- 两端偏好独立，不自动同步。已有 Bot 用户的迁移保留中文偏好。

## 翻译文件

| 范围 | 位置 |
| --- | --- |
| Web 语言注册、识别和持久化 | `frontend/src/i18n/registry.ts` |
| Web 翻译加载与回退 | `frontend/src/i18n.ts` |
| Web 中文、英语、俄语资源 | `frontend/src/locales/zh-CN/`、`en/`、`ru/` |
| Bot 语言注册、中文与英语资源、格式化 | `backend/src/i18n/telegram.ts` |
| Bot 俄语资源 | `backend/src/i18n/telegramRussian.json` |

新增或修改文案时：

1. 使用稳定的语义键，不用整句展示文本作为业务标识。
2. 同步各语言的键、插值变量和复数形式；日期、数字、时长和文件大小按当前语言格式化。
3. 翻译消息正文、按钮、回调提示、错误和后台通知，不只翻译标题。
4. 保持命令名、回调数据、状态值、权限作用域和数据库枚举不变。
5. 命令菜单只翻译描述，各语言保留相同的命令名和顺序。后台通知使用接收用户的语言。

新增语言还需更新语言注册表、别名、资源加载和 Bot 偏好的数据库约束，不能只添加翻译文件。

## 账号安全

语言选择只能保存偏好和更新界面，不得连接、恢复或启用个人 Telegram 账号，不得修改 session、允许列表或认证状态，也不得启动订阅扫描、任务恢复或重新配置 Bot。

个人账号仅可在完成登录或明确启用后连接。安全确认、权限校验、账号冷却和破坏性操作提示在各语言下必须保持相同含义。

## 验证范围

- 检查各语言资源键和插值变量是否一致，以及缺失翻译是否回退到中文。
- 验证首次设置、登录、文件操作、任务、设置和错误提示。
- 检查 Bot 实际发送/编辑的消息与键盘，包括取消、帮助、通知和危险操作确认。
- 验证刷新、Bot 重启后的语言保留，以及不受支持语言的回退。
- 检查英语和俄语长文本是否截断或遮挡操作按钮。
- 使用隔离测试验证语言切换不激活账号；不要为翻译验收登录或启用真实账号。

资源检查通过不等于 Web 或 Telegram 实际交互验收通过；发布前仍需逐语言检查关键流程。
